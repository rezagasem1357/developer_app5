# ارتباط شبکه

این نسخه زیرساخت اولیه ارتباط آنلاین/آفلاین را اضافه می‌کند.

## سرویس انتخاب‌شده
Supabase Free + Realtime/REST + Edge Functions در ادامه پروژه.
FCM برای Push Notification نیز در مرحله بعد اضافه می‌شود.

## راه‌اندازی
1. یک پروژه رایگان Supabase بسازید.
2. فایل `supabase/schema.sql` را در SQL Editor اجرا کنید.
3. در ابزار «ارتباط با شبکه» آدرس پروژه، Publishable/Anon Key و شناسه فروشگاه را وارد کنید.
4. مدیر می‌تواند «ارسال بانک» و صندوق‌دار «دریافت بانک» را انجام دهد.
5. رویدادهای محلی در صف outbox ذخیره می‌شوند و بعد از اتصال ارسال می‌شوند.

## محدودسازی بر اساس لایسنس
از این نسخه به بعد، همگام‌سازی فقط بین دستگاه‌هایی انجام می‌شود که **لایسنس یکسانی** داشته باشند
(همان لایسنسی که هنگام ورود در صفحه لاگین وارد و تأیید می‌شود). این کار با ترکیب لایسنس و شناسه
فروشگاه در یک شناسه واحد (`لایسنس__شناسه‌فروشگاه`) انجام می‌شود، پس حتی اگر چند مشتری مختلف از یک
پروژه Supabase مشترک استفاده کنند، بانک اطلاعاتی و رویدادهای هر لایسنس کاملاً از بقیه جدا می‌ماند.
اگر لایسنس روی دستگاهی خالی باشد (یعنی کاربر هنوز از صفحه ورود عبور نکرده)، دکمه‌های همگام‌سازی/ارسال/
دریافت غیرفعال می‌مانند و پیام خطا نمایش داده می‌شود.

اگر قبلاً `schema.sql` را روی پروژه Supabase اجرا کرده‌اید، کافی است همان فایل را دوباره در SQL
Editor اجرا کنید؛ خطوط `alter table ... add column if not exists` ستون `license` را بدون از دست
رفتن داده‌های قبلی اضافه می‌کنند.

## نکته امنیتی
policy های SQL فعلی فقط برای راه‌اندازی اولیه هستند و دسترسی عمومی دارند. قبل از استفاده چندکاربره واقعی، باید Supabase Auth و RLS مبتنی بر `auth.uid()` و نقش مدیر/صندوق‌دار فعال شود. کلید service_role هرگز نباید داخل Flutter قرار گیرد.

## Push واقعی در حالت بسته
برای اعلان زمانی که برنامه بسته است، در مرحله بعد FCM و یک Edge Function امن برای ارسال Push اضافه می‌شود. این مرحله نیازمند تنظیم Firebase Android (فایل google-services.json) است.
